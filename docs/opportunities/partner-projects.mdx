# Partner & Community Projects

Ubujima is building an ecosystem where developers can collaborate not only on Ubujima technology, but also on selected projects from founders, startups, organizations, agencies, nonprofits, research teams, and members of the broader community.

Partner & Community Projects provide developers with opportunities to apply their skills to real technology initiatives while helping project owners connect with contributors who want to build, learn, experiment, and create impact.

Projects featured here are reviewed before being introduced to the developer community.

---

# Project Categories

Projects within the Developer Hub may fall into three categories.

## Ubujima Projects

These are products, platforms, infrastructure, or technical initiatives owned or operated by Ubujima.

Examples include:

- AfroCom
- Ma'at AI
- Maji
- Ubujima developer infrastructure

Ubujima defines the technical direction, contribution model, governance, and repository structure for these projects.

## Partner Projects

Partner Projects are developed in collaboration with organizations, founders, companies, institutions, or other partners that have an established relationship with Ubujima.

The project may remain owned by the partner while being supported through collaboration with the Ubujima developer ecosystem.

Each Partner Project may have its own:

- Technical architecture
- Repository
- Development roadmap
- Licensing
- Contribution requirements
- Governance
- Compensation arrangements

The specific relationship between Ubujima and the project owner will be defined separately.

## Community Projects

Community Projects are selected projects that may benefit from visibility and developer collaboration through the Ubujima ecosystem but are not owned or operated by Ubujima.

Community Projects may be submitted by:

- Individual developers
- Founders
- Startups
- Agencies
- Nonprofits
- Community organizations
- Research groups
- Educational institutions

Ubujima may help make these opportunities discoverable without assuming ownership or operational responsibility for the project.

# Ways Developers Can Contribute

Depending on the project, opportunities may include:

- Frontend development
- Backend development
- Mobile development
- API development
- DevOps and infrastructure
- Artificial intelligence
- Data engineering
- Blockchain development
- UI/UX
- Testing and quality assurance
- Accessibility
- Documentation
- Security
- Technical research

Some projects may offer individual issues suitable for new contributors, while others may need experienced developers, coordinated teams, or development agencies.

# How Projects Will Be Presented

Each listed project should provide enough information for developers to understand the opportunity before participating.

A typical project listing may include:

### Project Name

**Classification:** Partner Project / Community Project

**Status:** Recruiting Contributors

Short description of the project and the problem it is working to solve.

**Technology**

React · Node.js · PostgreSQL

**Looking For**

Frontend · Backend · UI/UX · Testing

**Contribution Model**

Open Source / Volunteer / Paid / Bounty / Other

**Project Owner**

Organization or responsible project team.

**Repository**

Link to the development repository where publicly available.

**Get Involved**

Instructions for reviewing issues, contacting maintainers, or joining the project.

# Contribution Models

Projects may use different contribution models.

## Open Source

Contributions are made through a repository governed by a defined open-source license.

## Volunteer / Community Contribution

Contributors participate voluntarily in a community, nonprofit, educational, experimental, or other collaborative initiative.

## Paid Opportunities

Some projects may provide paid development work, contracts, internships, or other forms of compensation.

## Bounties

Individual issues or development tasks may include a defined reward for successful completion.

## Other Incentives

Some projects may offer other arrangements such as equity, revenue sharing, contributor recognition, or project-specific rewards.

Any compensation or incentive must be defined by the responsible project owner.

Participation in the Ubujima Developer Hub does not by itself create a right to compensation.

---

# Working With Project Owners

Every active Partner or Community Project should identify a responsible project owner or maintainer.

Project maintainers are expected to:

- Define meaningful contributor work
- Maintain project documentation
- Respond to contributor questions
- Review pull requests
- Manage issues
- Communicate technical direction
- Protect repository and infrastructure security
- Clearly communicate licensing and contribution terms

Developers should review the project's documentation and contribution requirements before beginning substantial work.

---

# Repository and Access

Projects may operate from:

- Public repositories
- Private repositories
- The project owner's GitHub organization
- Another approved source-control environment
- The Ubujima GitHub organization where specifically agreed

Being featured in the Developer Hub does not automatically give a project access to the Ubujima GitHub organization.

Similarly, contributors should only receive the repository, infrastructure, or development access required for their work.

Production credentials, user data, private keys, and other sensitive resources should never be exposed unnecessarily.

---

# Ownership and Licensing

Projects remain subject to their own ownership and licensing arrangements.

Being listed in the Ubujima Developer Hub does not transfer ownership of a project to Ubujima.

Project owners are responsible for clearly communicating:

- Project ownership
- Software licensing
- Contribution terms
- Intellectual-property requirements
- Any Contributor License Agreement
- Any confidentiality requirements
- Any compensation arrangements

Developers should understand these terms before making substantial contributions.

---

# Project Review

Before a project is featured, Ubujima may review areas including:

- Project purpose
- Ownership
- Technical scope
- Repository readiness
- Licensing
- Intellectual property
- Security and privacy
- Contributor requirements
- Project leadership
- Community suitability

Ubujima may decline, pause, or remove projects that no longer meet ecosystem requirements or lack active project leadership.
