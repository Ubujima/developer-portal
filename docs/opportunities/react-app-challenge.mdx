# React App Challenge

The **AfroCom React App Challenge** invites individual developers, development teams, and software agencies to help build the next generation of the AfroCom web application.

This is not only a competition.

It is also a collaborative development initiative where participants can work together, select issues or development tasks, contribute specific parts of the application, or independently build and submit a complete solution.

The goal is to bring developers together around a real product while creating meaningful opportunities to contribute, learn, collaborate, and demonstrate technical capability.

## What We Are Building

AfroCom is the flagship platform of Ubujima Corporation.

The immediate focus of the React App Challenge is to build and strengthen AfroCom's **community networking experience** using React and modern web technologies.

The challenge should initially focus on the capabilities of the existing AfroCom application rather than attempting to implement the entire long-term AfroCom super-app vision.

Core areas may include:

- User onboarding and authentication
- User profiles
- Community feeds
- Posts and content sharing
- Social connections
- Discovery
- Search
- Community interaction
- Business and opportunity discovery
- Notifications
- Responsive web experiences
- API and backend integration

Additional functionality may be introduced progressively through issues, milestones, and future development phases.

# Ways to Participate

Participants may contribute in two primary ways.

## 1. Collaborative Contribution

Individual developers, teams, and development agencies can participate by selecting available GitHub issues, tasks, features, or related groups of issues.

Contributors may work independently or collaborate with other participants.

Examples include:

- Building a UI component
- Implementing a page
- Integrating an API
- Improving responsiveness
- Fixing bugs
- Developing a feature
- Improving accessibility
- Writing tests
- Improving documentation
- Working on backend services
- Improving developer tooling

Larger teams or agencies may also take responsibility for a related group of tasks or a defined development area.

Participants should coordinate through the project's contribution workflow to reduce duplicated work and conflicting implementations.

## 2. Complete App Submission

A developer, team, or development agency may choose to independently build a complete React implementation of the AfroCom community networking application.

Complete implementations can be submitted for technical review and evaluation.

A complete submission does not automatically replace the existing application or guarantee production deployment.

Ubujima may evaluate complete implementations based on architecture, user experience, maintainability, performance, security, code quality, scalability, and alignment with AfroCom's product direction.

Strong ideas or implementations may also be incorporated into the broader project through collaboration with the development community.

# Backend Options

Participants building the React application may work with one of two backend approaches.

## Option A — AfroCom Supabase Backend

Participants may integrate with a designated **non-production AfroCom Supabase environment**.

This provides a faster path for developers who want to focus primarily on the React application, product experience, frontend architecture, and integration with existing AfroCom capabilities.

The challenge environment must not expose or provide access to AfroCom's production infrastructure or production user data.

Access, credentials, API documentation, environment variables, and development requirements will be provided according to contributor needs and project access policies.

This approach is particularly suitable for:

- Frontend contributors
- UI/UX implementation
- Feature development
- Rapid prototyping
- Existing API integration
- Developers contributing individual issues or components

## Option B — Scalable Microservices Backend

Participants may also propose or build a new backend architecture using scalable microservices.

The objective is not to recreate every future AfroCom service immediately.

The initial backend should focus on the requirements of AfroCom's **community networking platform as it exists today**, while establishing a foundation that can evolve into a broader service-oriented architecture over time.

A microservices implementation should prioritize:

- Clear service boundaries
- API-first architecture
- Maintainability
- Security
- Scalability
- Observability
- Containerized deployment
- Environment isolation
- Documentation
- Testability
- Progressive expansion

Possible service domains may eventually include:

- Authentication and identity
- User profiles
- Social graph and connections
- Posts and content
- Discovery
- Search
- Notifications
- Communication
- Media
- Business and opportunity services

Participants are not expected to implement all future AfroCom microservices as part of the initial challenge.

The first milestone should demonstrate a reliable architecture capable of supporting the current community networking experience and evolving progressively as AfroCom expands.

# Frontend Direction

The web application should be developed using **React** and the technologies defined by the challenge's technical requirements.

Participants should prioritize:

- Modular architecture
- Reusable components
- Responsive design
- Accessibility
- Performance
- Maintainability
- Clear state management
- Clean API integration
- Secure development practices
- Testing
- Documentation

Where official AfroCom designs, user flows, design systems, or Figma resources are provided, participants should use them as the primary product reference.

# Working Through GitHub

Development will be coordinated through GitHub.

Participants will be able to identify available work through:

- Issues
- Feature requests
- Development tasks
- Milestones
- Technical discussions
- Documentation tasks
- Backend tasks
- UI/UX implementation tasks

Before beginning substantial work, contributors should review the relevant issue and communicate their intention to work on it.

Where appropriate, issues may be assigned to contributors or teams to reduce duplicated effort.

Development agencies or teams interested in taking responsibility for a larger development area should coordinate with Ubujima before beginning the work.

# Contribution Workflow

A typical contribution may follow this process:

1. Explore the project and documentation.
2. Review available GitHub issues.
3. Select an issue or development area.
4. Coordinate with maintainers where necessary.
5. Create a branch or fork.
6. Build and test the contribution.
7. Submit a pull request.
8. Participate in technical review.
9. Address requested changes.
10. Merge approved contributions.

Participants should also review the [Contribution Guide](../getting-started/contribution-guide) and [Developer Onboarding](../getting-started/developer-onboarding) documentation.

# For Development Agencies

Software agencies are welcome to participate.

An agency may:

- Contribute individual features
- Take ownership of related groups of issues
- Collaborate with individual contributors
- Provide specialist engineering capacity
- Work on frontend or backend infrastructure
- Submit a complete implementation

Participation in the challenge does not automatically establish a commercial contract, vendor relationship, equity arrangement, or entitlement to compensation.

Any commercial engagement, compensation, incentive, award, or other arrangement must be separately agreed with Ubujima.

# Evaluation

Contributions and complete implementations may be evaluated based on factors such as:

- Functional quality
- User experience
- Technical architecture
- Code quality
- Maintainability
- Performance
- Security
- Accessibility
- Documentation
- Testing
- Scalability
- Collaboration
- Alignment with AfroCom's product direction

Different contribution types may be evaluated differently.

A contributor implementing one excellent service or feature should not necessarily be compared directly with a team submitting an entire application.

---

# Open Source and Intellectual Property

The React App Challenge is designed to encourage collaborative development.

However, participants must only contribute code, assets, libraries, designs, and other materials they have the legal right to contribute.

Repository-specific licensing and contribution requirements will apply.

Participation does not automatically grant access to private Ubujima repositories, production systems, confidential information, or proprietary technology.

Additional agreements may be required for certain development areas.
